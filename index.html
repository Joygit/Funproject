🌐 1. What is a Network?

A computer network is a collection of two or more devices (computers, servers, phones, printers) connected together so they can communicate and share resources — like files, internet connections, and printers.

📤 Why do we need Networks?

Share files & data instantly · Share internet bandwidth · Centralise storage (servers) · Enable communication (email, video calls) · Run cloud & enterprise apps

🔑 Key Network Terms

Node: Any device on the network
Host: A node that sends/receives data
Protocol: Rules two devices agree on
Bandwidth: Data capacity of the link

💡 Real-world analogy: A network is like a postal system. Devices are houses, IP addresses are postal addresses, routers are sorting centres, and data packets are letters.

📦 3. Router — What It Is & How It Works

A router is a Layer-3 (Network Layer) device. Its job is to decide the best path for data packets to travel between different networks.

How a Router Works — Step by Step

1

Receives a Packet

A data packet arrives on one of the router's interfaces (ports) from a device.

2

Reads Destination IP

The router reads the packet's destination IP address in the Layer-3 header.

3

Looks Up Routing Table

It checks its routing table — a list of networks and the next-hop IP or interface to reach them.

4

Forwards the Packet

Sends the packet out on the correct interface toward the destination. Decrements TTL by 1.

💡 Key point: A router connects different networks. It works at IP (Layer 3). Unlike a switch, it understands IP addresses — not just MAC addresses.

🔀 4. Switch — What It Is & How It Works

A network switch is a Layer-2 device that connects devices within the same network (same LAN). It uses MAC addresses to forward frames to the correct device only — unlike an old hub which broadcast to everyone.

Hub vs Switch

Hub: Broadcasts packets to ALL ports — inefficient, security risk.
Switch: Sends packets ONLY to the destination MAC — efficient, secure.

L2 vs L3 Switch

L2 Switch: Works with MAC addresses only, within a single LAN.
L3 Switch: Can also route between VLANs using IP addresses.

🔗 5. LAN — Local Area Network

A LAN is a network that covers a small geographic area — a home, office, or building. All devices share the same network address space and can communicate without going through a router.

🔢 6. IP Address — The Basics

An IP address (Internet Protocol address) is a unique numerical label assigned to every device on a network. It's how devices find and talk to each other — like a postal address for data.

IPv4 Structure

An IPv4 address is 32 bits long, written as 4 octets separated by dots.
Example: 192.168.1.100
In binary: 11000000 . 10101000 . 00000001 . 01100100

Network Part

Identifies which network the device is on. Like the city + street in a postal address.

Host Part

Identifies the specific device within that network. Like the house number.

Broadcast

Address where all host bits = 1. A packet sent here goes to ALL devices on the subnet.

🅰 7. IP Address Classes — A, B, C, D, E

IPv4 addresses were originally divided into classes based on the first octet. This determined the size of the network and host portions.

Class A
1.0.0.0 – 126.255.255.255

First bit: 0
Network bits: 8 | Host bits: 24
Hosts per network: ~16 million
Use: Very large enterprises, ISPs

Default Mask: /8 → 255.0.0.0
Class B
128.0.0.0 – 191.255.255.255

First bits: 10
Network bits: 16 | Host bits: 16
Hosts per network: ~65,000
Use: Medium-large organisations

Default Mask: /16 → 255.255.0.0
Class C
192.0.0.0 – 223.255.255.255

First bits: 110
Network bits: 24 | Host bits: 8
Hosts per network: 254
Use: Small offices, home networks

Default Mask: /24 → 255.255.255.0
Class D
224.0.0.0 – 239.255.255.255

First bits: 1110
No host/network split
Use: Multicast groups (streaming, OSPF, routing protocols)

No subnet mask
Class E
240.0.0.0 – 255.255.255.255

First bits: 1111
Reserved — experimental use only.
255.255.255.255 = limited broadcast

Reserved / Experimental
⚠️ Important: Classful addressing is largely obsolete today. Modern networking uses CIDR (Classless Inter-Domain Routing) which ignores class boundaries and uses a prefix length (e.g., /22) to define network size.

🎭 8. Subnet Mask

A subnet mask tells a device which part of an IP address is the network and which part is the host. It's also 32 bits, written in dotted-decimal or as a prefix length (CIDR notation).

Example: IP = 192.168.1.50 | Mask = 255.255.255.0 (/24)
Binary AND of IP & Mask → Network address = 192.168.1.0
Host range: 192.168.1.1 – 192.168.1.254 | Broadcast: 192.168.1.255

📐 9. CIDR Block Calculation

CIDR (Classless Inter-Domain Routing) replaces the old class system. You specify how many bits are the "network" part using a /prefix after the IP.

Step-by-Step CIDR Calculation

Given: 10.0.0.0/22 — find the network address, broadcast, host range, and total hosts. 
1. Prefix = /22 → 22 bits for network, 10 bits for hosts
2. Total addresses = 2^(32-22) = 2^10 = 1024
3. Usable hosts = 1024 - 2 = 1022

4. Network address: 10.0.0.0
5. Broadcast:       10.0.3.255  (last address in the block)
6. First host:      10.0.0.1
7. Last host:       10.0.3.254

Binary check:
10.0.0.0  = 00001010.00000000.00000000.00000000
Mask /22  = 11111111.11111111.11111100.00000000
                                     ^^  ← 2 host bits in 3rd octet
Host range spans: 10.0.0.x → 10.0.3.x (4 × 256 = 1024)
How many subnets can I make?

If you borrow n bits from host part:
Subnets = 2^n
E.g., from /24, borrow 2 bits → /26 → 4 subnets, each with 62 hosts

Subnet increment

Block size = 256 - last non-zero mask octet
/26 → mask = 255.255.255.192 → 256-192 = 64
Subnets: .0, .64, .128, .192

Azure reserved addresses

In every Azure subnet, 5 IPs are reserved:
.0 Network · .1 Gateway · .2 DNS · .3 DNS · .255 Broadcast

Quick CIDR cheat

/24 = 256 IPs · /23 = 512 · /22 = 1024 · /21 = 2048
Each step down doubles the addresses.

☁ 10. Azure Virtual Network (VNet)

An Azure Virtual Network (VNet) is the fundamental building block of your private network in Azure. It's the cloud equivalent of a traditional LAN — fully isolated, defined by an IP address space, and divided into subnets.

What VNet gives you

✅ Isolated private IP space
✅ Subnets to segment workloads
✅ Route traffic between subnets
✅ Connect to on-premises via VPN/ExpressRoute
✅ Filter traffic with NSGs and firewalls

VNet scope

A VNet lives in one Azure Region (e.g., East US). VNets in different regions can connect via VNet Peering. A VNet belongs to one Resource Group and one Subscription.

💡 Think of VNet as the walls of your building in Azure. Everything inside can talk to each other. Nothing outside can enter unless you explicitly allow it.

🧱 11. Azure Network Components — Explained

🏗

Resource Group

A logical container that holds all Azure resources for a project. Think of it as a folder. All network components (VNet, NSG, VMs) live inside it.

🌐

Virtual Network (VNet)

The private network. You assign an address space, e.g., 10.0.0.0/16. All subnets and VMs live within this space. Isolated from other VNets by default.

🔲

Subnet

A subdivision of the VNet address space. Used to segment workloads (e.g., web-subnet, db-subnet). Each subnet gets a CIDR block from the VNet range. Azure reserves 5 IPs per subnet.

🛡

Network Security Group (NSG)

A stateful firewall. Contains inbound and outbound rules that allow or deny traffic based on source IP, destination IP, port, and protocol. Attached to subnets or NICs.

🌍

Public IP Address

Assigns a publicly routable IP to a VM or Load Balancer so it can be reached from the internet. Can be static or dynamic.

🔌

Network Interface Card (NIC)

The virtual network adapter attached to a VM. Gets a private IP from the subnet. Can optionally have a public IP attached. A VM can have multiple NICs.

📋

Route Table (UDR)

User Defined Routes let you override default Azure routing. E.g., force all traffic through a firewall VM before it leaves the subnet.

⚖

Azure Load Balancer

Distributes inbound traffic across multiple VMs in a backend pool. Works at Layer 4 (TCP/UDP). Keeps apps available even if one VM fails.

🔒

VPN Gateway

Connects your Azure VNet to your on-premises network or another VNet over an encrypted IPsec tunnel through the internet.

🔁

VNet Peering

Connects two VNets (same region or cross-region) privately via Azure backbone — no internet, no VPN. Traffic stays on Microsoft's network at low latency.

🗣

Azure DNS

Provides name resolution for resources within a VNet using private DNS zones. VMs can resolve each other by hostname instead of IP.

🖥 13. Deploy Azure VMs in a Network

Here's how to deploy a Virtual Machine inside your Azure VNet, step by step.

Prerequisites — Build the Network First

1

Create a Resource Group

Portal → Resource Groups → + Create → Name: rg-myapp, Region: East US → Review + Create

2

Create a Virtual Network

Portal → Virtual Networks → + Create → VNet name: vnet-myapp, Address space: 10.0.0.0/16

3

Add Subnets

Inside VNet → Subnets → + Subnet → Name: snet-web, Range: 10.0.1.0/24. Repeat for app (10.0.2.0/24) and db (10.0.3.0/24).

4

Create NSG

Portal → Network Security Groups → + Create → Name: nsg-web. Add inbound rule: Allow TCP port 80 from Internet. Deny all else.

5

Associate NSG with Subnet

In the NSG → Settings → Subnets → Associate → pick snet-web.

Deploy a VM Into the Network

6

Create Virtual Machine

Portal → Virtual Machines → + Create → Azure Virtual Machine

7

Basics Tab

Resource Group: rg-myapp · VM Name: vm-web01 · Region: East US · Image: Ubuntu 22.04 LTS · Size: Standard_B1s · Auth: SSH key or password

8

Networking Tab ← Most Important

Virtual Network: vnet-myapp · Subnet: snet-web (10.0.1.0/24) · Public IP: Create new (or None for private-only) · NIC NSG: select existing NSG nsg-web

9

Review + Create

Azure validates → click Create. VM gets private IP (e.g., 10.0.1.4) from subnet's DHCP pool automatically.

10

Connect to VM

Via public IP using SSH: ssh azureuser@<public-ip>. Or use Azure Bastion for browser-based access without opening port 22 to internet.

✅ Result: Your VM (vm-web01) is now deployed with private IP 10.0.1.4 inside snet-web, protected by nsg-web, reachable on port 80 from the internet through its public IP or a Load Balancer.
